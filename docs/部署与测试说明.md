本文件用于指导如何在本地或服务器环境中部署并运行 Yatmosphere 智能家居控制系统，包括前端、后端和设备网关的部署与操作步骤。

## 1. 前提准备

- 操作系统：Windows / macOS / Linux 均可，根据实际环境选择对应命令。
- 已安装工具：
  - Git
  - Node.js（建议 14+ 版本）与 npm 或 Yarn
  - Java 17（用于后端）
  - Maven 3.x（用于后端构建）
  - Python 3.11+（用于网关和虚拟设备）
  - MySQL 8.x（或以上版本）
  - Docker（用于部署 MQTT Broker，可选）
  - 终端工具（如 PowerShell、bash 等）

## 2. 克隆仓库

在工作目录下执行：

```bash
git clone https://github.com/sysu-orz/yatmosphere.git
cd yatmosphere
```

```

├── README.md
```

## 3. 前端部署

### 3.1 进入前端目录

```bash
cd frontend
```

### 3.2 安装依赖

```bash
npm install
```

### 3.3 配置环境变量

在 `frontend` 根目录下创建 `.env` 或 `.env.local`，内容示例（根据实际后端地址调整）：

```env
VITE_API_BASE_URL=http://localhost:81
VITE_APP_TITLE=Yatmosphere
VITE_THEME=light
```

- `VITE_API_BASE_URL`：后端服务地址及端口，如本地默认 `http://localhost:81`。
- `VITE_APP_TITLE`：页面标题，可自行修改。
- `VITE_THEME`：默认主题 `light` 或 `dark`。

### 3.4 本地开发模式

```bash
npm run dev
```

- 启动后可在浏览器访问 `http://localhost:5173`（默认端口，若有变动请根据终端日志确认）。
- 使用 Vue Devtools 调试，如需热重载，修改源码后自动刷新。

### 3.5 生产构建

```bash
npm run build
```

- 构建结果输出在 `dist/` 目录。
- 将 `dist/` 下文件部署到静态服务器或 CDN，确保前端能正确请求后端 API。

## 4. 后端部署

### 4.1 进入后端目录

```bash
cd ../backend
```

（假设前面在 `frontend`；如从根目录执行可 `cd backend`）

### 4.2 配置数据库

- 确保 MySQL 服务已启动，记住用户名/密码。
- 创建数据库：

  ```bash
  mysql -u root -p
  # 输入密码后，在 MySQL 提示符运行：
  CREATE DATABASE IF NOT EXISTS library CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  EXIT;
  ```
- 导入建表脚本：

  ```bash
  mysql -u root -p iot < path/to/sql/iot.sql
  ```

  注意将 `path/to/sql/iot.sql` 替换为实际脚本路径，如 `backend/sql/iot.sql`。

### 4.3 配置 Spring Boot 环境

在 `backend/src/main/resources` 下，有配置文件 `application.yml` 或 `application-dev.yml`。请根据环境修改数据库连接信息，例如：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/iot?useSSL=false&serverTimezone=UTC
    username: root
    password: your_password
  jpa:
    hibernate:
      ddl-auto: none
    show-sql: false
server:
  port: 81
```

- `url`、`username`、`password` 请与本地 MySQL 配置保持一致。
- `server.port`：后端监听端口，可根据需要修改（前端环境变量需对应）。

### 4.4 添加 Maven 到 PATH（Windows 示例）

```powershell
# PowerShell
$env:Path += ";D:\apache-maven-3.9.9\bin"
mvn -v  # 验证 Maven 可用
```

Linux/macOS 可在 shell 配置文件中导出 `PATH`。

### 4.5 运行后端

```bash
mvn spring-boot:run
```

- 启动成功后，控制台会显示类似：

  ```
  Tomcat started on port(s): 81 (http) with context path ''
  Started Application in X.XXX seconds
  ```
- 若需要打包为 jar：

  ```bash
  mvn clean package
  java -jar target/your-app-name.jar
  ```

### 4.6 接口测试

使用 Postman 或 curl 测试基本接口：

- 登录：

  ```
  POST http://localhost:81/auth/login
  Body: { "username": "...", "password": "..." }
  ```
- 注册：

  ```
  POST http://localhost:81/auth/register
  ```
- 查看用户详情：

  ```
  GET http://localhost:81/user/detail?account=xxx
  ```
- 设备管理接口示例：

  ```
  GET/POST http://localhost:81/device/...
  ```

注意：所有需要认证的请求需在 Header 中添加 `Authorization: Bearer <token>`。

## 5. 设备网关部署

### 5.1 进入网关目录

```bash
cd ../gateway
```

### 5.2 安装依赖

建议使用虚拟环境：

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Linux/macOS
source venv/bin/activate

pip install -r requirements.txt
```

### 5.3 配置 MQTT Broker 地址

在网关配置文件（如 `config.yaml` 或代码中的默认配置）中，设置 MQTT Broker 地址，若本地运行 EMQX，一般为 `localhost:1883`。示例 `config.yaml`：

```yaml
mqtt:
  host: "localhost"
  port: 1883
  username: ""
  password: ""
```

### 5.4 启动网关

```bash
export PYTHONPATH=$PYTHONPATH:$(pwd)    # Linux/macOS
# Windows PowerShell: $env:PYTHONPATH = "$pwd;$env:PYTHONPATH"

python src/main.py
```

- 启动后会连接到 MQTT Broker，并订阅必要主题。
- 控制台会打印连接状态、订阅主题等日志。

## 6. MQTT Broker（EMQX）部署

### 6.1 本地快速启动（Docker）

若本地测试，可使用 Docker 快速启动 EMQX：

```bash
docker run -d --name emqx -p 1883:1883 -p 8083:8083 emqx/emqx:latest
```

- 默认 MQTT 端口 1883，用于设备与网关通信。
- 8083 用于 WebSocket 等，可视化监控（若需要）。

### 6.2 生产环境部署

- 可部署 EMQX 集群或使用其他 MQTT Broker（如 Mosquitto、HiveMQ 等）。
- 确保 Broker 支持必要的并发连接与安全配置。
- 若有认证需求，可在 Broker 侧配置用户、密码或 TLS 证书。

## 7. 配置环境变量

可通过环境变量或配置文件统一管理关键参数：

- 后端：
  - `SPRING_DATASOURCE_URL` / 在 `application.yml` 中配置
  - 数据库用户名/密码
  - 服务端口 `SERVER_PORT`（如 81）
- 前端：
  - `VITE_API_BASE_URL`
  - `VITE_APP_TITLE`
  - `VITE_THEME`
- 网关：
  - MQTT Broker 地址、端口、账号密码
  - 日志级别等

在不同环境（开发/测试/生产）下，可使用不同的配置文件或环境变量进行区分。

## 8. 运行与验证

1. **启动 MQTT Broker**（确保网关与后端可连通）：

   ```bash
   docker run -d --name emqx -p 1883:1883 -p 8083:8083 emqx/emqx:latest
   ```
2. **启动后端服务**：

   ```bash
   cd backend
   mvn spring-boot:run
   ```
3. **启动设备网关**：

   ```bash
   cd gateway
   source venv/bin/activate  # 如果使用虚拟环境
   python src/main.py
   ```
4. **启动前端**：

   ```bash
   cd frontend
   npm run dev
   ```
5. **访问前端页面**：
   打开浏览器访问 `http://localhost:5173`，进行登录、设备控制等操作。
6. **测试示例**：

   - 通过前端界面操作设备，观察后端日志及网关日志，确认 MQTT 消息收发正常。
   - 也可使用 `mosquitto_pub/sub` 进行手动测试，示例：

     ```bash
     # 订阅设备响应
     mosquitto_sub -h localhost -t "device/light_001/response" -v
     # 发送命令
     mosquitto_pub -h localhost -t "device/light_001/command" -m '{"msg_id": "1","msg_type":"command","device_type":"light","device_id":"light_001","action":"set_power","value":"on"}'
     ```
7. **连通性检查**：

   - 确认前端能正确调用后端 API。
   - 确认后端能通过 MQTT Broker 与网关通信。
   - 确认网关能与物理设备或虚拟设备交互。

## 9. 常见问题与排查

- **前端启动报错**
  - 检查 Node.js 版本，确保与项目需求一致。
  - 检查环境变量 `VITE_API_BASE_URL` 是否正确指向后端地址。
  - 若依赖安装失败，可删除 `node_modules` 后重装。
- **后端无法启动或连接数据库失败**
  - 检查 MySQL 服务是否启动，数据库已创建且脚本已导入。
  - 检查 `application.yml` 中的 URL、用户名、密码是否正确。
  - 确保防火墙或安全组放通数据库端口（生产环境）。
- **MQTT 连接失败**
  - 确认 MQTT Broker 已启动且地址/端口正确。
  - 检查网关配置中的 Broker 地址、用户名/密码。
  - 本地测试时，Docker 容器与主机网络连通性问题，可用 `--network host`（Linux）或映射端口。
- **网关运行时报错**
  - 检查 Python 依赖是否安装完整（`pip install -r requirements.txt`）。
  - 查看日志定位订阅主题或 JSON 解析错误。
  - 若使用虚拟设备，确认模拟脚本正常运行。
- **跨域问题（CORS）**
  - 后端需配置允许前端地址跨域访问，检查 Spring Boot CORS 设置。
  - 前端开发模式下，可在代理配置（如 `vite.config.js`）中设置代理到后端。
- **认证或 Token 问题**
  - 登录后获取的 JWT Token 是否正确附加到前端请求 Header 中。
  - 后端验证逻辑、Token 过期设置等是否符合需求。
- **环境不同导致的问题**
  - 开发/测试/生产环境配置要分离，确保正确加载对应配置文件或环境变量。
  - 注意时区、字符编码等差异。
